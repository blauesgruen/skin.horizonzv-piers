## Review scope and method

- Searched the active skin XML for InfoLabels, boolean conditions, built-ins, removed names, and current Kodi deprecation markers. Counts and locations below are checkout references, not runtime call counts.
- Compared hits with the official Kodi skinning changes, InfoLabel, boolean-condition, and built-in references. For removal/deprecation status, Kodi references and source take precedence over third-party forum advice.
- Rechecked the current official Kodi 23 development pages on 2026-10-29. The skinning page lists one removal (`gamewindow`'s `pixels` tag) and otherwise additions/expanded labels; the Python v23 page lists additions only and no removals/deprecations. These pages are forward-compatibility evidence, not a prediction of unannounced changes.
- Checked both tagged Kodi 22 / Piers source and current Kodi `master` documentation/source for versioned removals, deprecation annotations, and registered control types. The current Infolabels documentation and source comment table still display `Player.DisplayAfterSeek`, but the same source's v20 removal history says it was removed and the runtime parameter registry only maps `Player.HasPerformedSeek`. Treat this as stale, contradictory documentation; the versioned removal record and active parser registration take precedence. The additional removal-history section currently ends at Kodi 22, so future removals beyond published records cannot be predicted reliably.
- Kodi 22's latest official repository release entry is `v22.0rc1-Piers` (a pre-release). The Kodi 23 development documentation was therefore treated as a forward-compatibility signal, not as a claim that Kodi 23 is already released or supported by this checkout.
- Checked the Kodi 23 development skinning change page separately. It explicitly removes the gamewindow `pixels` tag; the Kodi 22 game-control reference documents that tag as a savestate-pixel preview. The two skin uses overlay `ListItem.Art(screenshot)` images already, so the obsolete tags were removed while retaining the screenshot-art path and active-game preview controls.
- Inspected the Kodi 22 installed Estuary XML and installed add-on files where available. This helps verify local compatibility examples but does not establish every provider or platform behavior.
- Compared the installed, skin-referenced Python add-on manifests and source against Kodi Python API change pages v19-v23, searching the documented removed methods and deprecations. The v21 and v23 change pages currently list additions only; v22 lists a deprecated `ListItem.setAvailableFanart()` method. This covered installed versions only; it does not prove future upstream updates remain compatible.
- Revalidated the Disney+ extra-fanart protection in the current checkout against Kodi Piers source. `String.StartsWith(info,substring)` is an active registered condition; `Player.FolderPath` and `ListItem.Path` are documented labels. The two variables return an empty path for `plugin://` URLs, and their `multiimage` controls also have plugin-path visibility guards. This is source evidence for the guard logic, not a CoreELEC runtime reproduction. The production skin contains no `.py`, `.pyw`, or `.js` runtime scripts; Python API calls relevant to its UI integrations are in external add-ons. The later-added `tools/check_skin_compatibility.py` is an offline developer check and uses no Kodi/Python add-on API.
- Kodi Piers RC1 reports Python 3.14.3. A targeted scan of installed skin-referenced add-on source also checked standard-library imports removed in Python 3.13/3.14; it found bundled compatibility-library references that need path-sensitive review, described below.
- This is not a literal search of every page on the internet. The skinning docs do not provide one complete machine-readable registry of every API by version; third-party APIs and runtime behavior remain separate review areas.
